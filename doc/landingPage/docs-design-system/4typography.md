# Typography

Version : 1.0

**Objectif**

La typographie doit permettre aux utilisateurs de trouver rapidement une information importante tout en restant confortable à lire.

**Elle doit transmettre :**

- simplicité ;
- confiance ;
- modernité ;
- sérénité.

## 1. Police principale

Je choisirais : **Inter**

Pourquoi ?

- excellente lisibilité ;
- pensée pour les interfaces ;
- gratuite ;
- variable font ;
- parfaitement adaptée au web.

Elle fonctionne aussi bien sur la landing que dans l'application.

## 2. Hiérarchie

La hiérarchie doit être évidente.

Sans utiliser beaucoup de couleurs.

Le texte doit parler tout seul.

### H1

Hero / Titre principal / Desktop : 48 px

Mobile : 36 px

Poids : 700

### H2

Titres de section / Desktop : 36 px

Mobile : 30 px

Poids :700

### H3 

Titre d'une carte / Titre d'un panneau : 28 px

Poids : 600

### H4 

Sous-sections : 24 px

Poids : 600

### Body Large 

Landing / Descriptions importantes : 20 px

Poids : 400

### Body

Le texte le plus utilisé : 18 px

Poids : 400

C'est volontairement un peu plus grand que les standards habituels, car une partie des utilisateurs sera peu à l'aise avec les petits caractères.

### Small

Descriptions secondaires :16 px

Poids :400

### Caption

Informations complémentaires : 14 px

Poids :400

À utiliser avec modération.

### Buttons

18 px

Poids :600

Jamais en majuscules.

Toujours avec une casse naturelle :

✅ Créer un CareGroup

❌ CRÉER UN CAREGROUP

## 3. Longueur des lignes

Une ligne trop longue fatigue.

Règle :

entre 60 et 75 caractères par ligne pour les paragraphes.

Sur desktop, limiter la largeur du texte plutôt que de l'étirer sur tout l'écran.

## 4. Alignement

Par défaut : Alignement à gauche.

Pourquoi ?

Plus rapide à lire.

Éviter les textes justifiés.

Les titres peuvent être centrés dans certaines sections marketing, mais pas dans l'application.

## 5. Contraste

Le contraste doit venir principalement :

- de la taille ;
- du poids ;
- des espacements.

Pas uniquement de la couleur.

## 6. Style d'écriture

Notre ton reste :

- simple ;
- humain ;
- rassurant.

Nous privilégions les phrases courtes.

Exemple :

❌ Veuillez procéder à l'ajout d'un nouveau rendez-vous.

✅ Ajoutez un rendez-vous.

Autre exemple :

❌ Le dossier a été correctement créé.

✅ Le dossier est prêt.

## 7. Utilisation du gras

Le gras sert à attirer l'œil.

Pas à décorer.

Limiter à :

- mots-clés ;
- informations importantes ;
- chiffres.

Éviter les paragraphes entièrement en gras.

## 8. Icônes et texte

Les icônes accompagnent le texte.

Elles ne le remplacent pas.

Exemple :

📅 Rendez-vous

✔️ Compréhensible.

📅 seul

❌ Peut prêter à confusion.

## 9. Accessibilité

**Objectifs :**

- taille minimale de 16 px pour le texte courant ;
- hauteur de ligne confortable (≈1,5) ;
- contraste conforme aux recommandations WCAG (au moins AA) ;
- éviter les textes en gris très clair.

## 10. Règles spécifiques à CareGroup

**Nous préférons :**

- "Votre proche" plutôt que "Le patient" dans les textes destinés aux familles.
- "Accompagner" plutôt que "Gérer".
- "Inviter un membre" plutôt que "Ajouter un utilisateur".
- "Créer un CareGroup" (ou le nom définitif) plutôt que "Créer un espace" si le concept est déjà connu de l'utilisateur.

Ces choix renforcent une communication plus humaine.

Exemples d'application : Hero / Accompagnez un proche, ensemble.

Centralisez les rendez-vous, les documents et les échanges dans un espace partagé conçu pour toute la famille.

[Créer un CareGroup]

On distingue immédiatement :

le message principal ;
l'explication ;
l'action.

## Évolution du Design System

À partir de maintenant, je pense que nous pouvons faire en sorte que chaque document se termine par une section :

"Impact sur l'application actuelle"

Par exemple, pour la typographie, on pourrait noter :

## Impact sur l'application actuelle

- Vérifier que les titres utilisent une hiérarchie cohérente.
- Uniformiser les tailles de texte entre les cartes, les formulaires et les tableaux.
- Remplacer les libellés trop techniques par un vocabulaire plus humain lorsque c'est pertinent.
- Vérifier que tous les textes courants sont au moins à 16 px, voire 18 px pour les écrans principaux.

Cette section transformera le Design System en plan d'amélioration progressif de ton application existante. 
Pas besoin de tout refaire : à chaque nouvelle fonctionnalité ou refonte d'une page, tu pourras appliquer une partie de ces recommandations. 
Je pense que c'est une façon très réaliste de faire évoluer le projet sans casser tout ce qui fonctionne déjà.
