# Le Design System n'est pas une bibliothèque de composants

C'est une erreur très fréquente.

Beaucoup pensent :

"Le Design System = les boutons."

Non.

Le Design System répond à une question beaucoup plus large :

"Comment concevons-nous les interfaces de CareGroup ?"

Les boutons ne sont qu'une conséquence.

## 01 - Foundations

Les règles qui ne changent jamais.

Exemples :

priorité à la lisibilité ;
une seule action principale par écran ;
les informations d'urgence sont toujours visibles ;
éviter les interfaces surchargées ;
toujours guider l'utilisateur.

Ce document est presque philosophique.

## 09 - Motion

Les animations.

Je pense qu'on peut faire quelque chose de très élégant :

ouverture de menu ;
apparition des cartes ;
hover des boutons ;
transitions de pages.

Sans jamais tomber dans l'effet "gadget".

## 10 - Accessibility

Et là, c'est très important pour ton projet.

Tes utilisateurs ne seront pas uniquement des développeurs de 25 ans.

On doit penser à :

une bonne taille de police ;
un contraste suffisant ;
des zones de clic confortables ;
des états de focus visibles ;
des messages d'erreur clairs ;
une navigation au clavier.

C'est une vraie valeur ajoutée pour une application destinée à des familles, parfois avec des utilisateurs plus âgés.

# Design Principles

## ❤️ 1. L'humain avant la technologie

Chaque décision de design doit d'abord servir les personnes qui accompagnent un proche, avant de mettre en avant la technologie.

## 🤝 2. Collaborer naturellement

L'application doit rendre le travail collectif évident, sans multiplier les manipulations ni les explications.

## 🌿 3. Simplifier le quotidien

Chaque fonctionnalité doit réduire la charge mentale des utilisateurs. Si une interface complique plus qu'elle n'aide, elle doit être repensée.
